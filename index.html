The most expensive part of software is the part that’s wrong.

That’s true with human teams. It’s triply true with LLM agents. So every engagement starts the same way: survey the terrain. The system as it actually runs, the team as it actually works, and the constraints nobody wrote down.

Then turn what you want into a contract, check the contract, and only then write the code. I work at every level of that, from writing production-grade code to leading engineering organizations, and I’ve spent the last few years making LLM-based development reliable enough to ship.

B The route · open-source toolchain

A gate at every turn.

All open source ↗

Every non-deterministic step in an agent workflow deserves a deterministic gate. These ten open-source tools are the gates I build with, and the working material behind most engagements.

  1. 01

    Specify

    Turn the idea into a contract, then attack the contract. Contradictions, hidden assumptions, and missing prerequisites surface before a line of code is written.

    specBuilder ↗ speccritic ↗
  2. 02

    Plan

    Review the implementation plan the same way: structured critique, ambiguities flagged, concrete patches returned.

    plancritic ↗
  3. 03

    Context

    Decide what the agent gets to see. Score, budget, and explain which files load, so context becomes a designed artifact instead of a guess.

    aperture ↗ atlas ↗
  4. 04

    Build

    The agent writes the code. What it did along the way is recorded, so “what did the agent actually do?” has an answer.

    witness ↗
  5. 05

    Review

    Check the diff, then check the intent: does the code match the spec and plan it was given, and only that?

    prism ↗ realitycheck ↗
  6. 06

    Verify

    Find the tests you don’t have, and scaffold honest skeletons for the ones that matter.

    verifier ↗
  7. 07

    Document

    Generate docs where every claim traces back to source, and detect the drift when the code moves on.

    clarion ↗
